# Token Budget 与 Chunked Prefill 对照实验

记录日期：2026-09-23。

## 结论

在同一台 RTX 4090、同一 Qwen3-8B 和同一 6 请求负载下，只把 `max-num-batched-tokens` 从 512 改为 4096：

- 512 的长输入组连续 3/3 批次出现 capacity Waiting，峰值为 2–3；4096 组 3/3 均为 0。两组 Running 峰值均为 6，低于 `max-num-seqs=8`，KV 峰值均不足 10%，Preemption 均为 0。因此这里是单轮 token budget 约束，不是请求名额或 KV 容量瓶颈。
- 长输入的服务端平均 TTFT 中位数从 0.5648 秒降到 0.4495 秒，符合大 budget 减少 chunked-prefill 轮次的机制；客户端 TTFT 受 SSH 链路波动影响，没有稳定复现同一方向。
- 混合负载中，4096 的服务端平均 ITL 中位数为 0.0203 秒，512 为 0.0195 秒，大约高 4.1%。这支持“大块 Prefill 可能略微干扰 Decode”，但差异很小，只适用于本次负载。
- 输出吞吐量不随 budget 单调增加：short 与 mixed 在 4096 下分别提高约 18.8% 和 42.8%，long 反而下降约 3.8%，且两组长输入范围重叠，不能宣称 4096 对所有工作负载更快。

## 环境与单变量

- GPU：NVIDIA GeForce RTX 4090 48GB；驱动 590.44.01。
- PyTorch 2.13.0+cu132；vLLM 0.29.0；模型 Qwen3-8B BF16。
- 固定：`max-model-len=4096`、`gpu-memory-utilization=0.75`、`block-size=16`、`max-num-seqs=8`、chunked prefill、prefix caching、`scheduler-reserve-full-isl`、`watermark=0`。
- 唯一主动改变的配置：`max-num-batched-tokens=512` 或 `4096`。
- 每个 budget、每种 shape 先预热 1 批，再正式运行 3 批；每批通过 Barrier 同时发送 6 个请求，固定生成 128 tokens。
- short 实际输入 173 tokens；long 实际输入 1955 tokens；mixed 为 3 short + 3 long。
- 每个正式批次 6/6 成功、总输出 768 tokens、`finish_reason=length`；18 个正式批次合计 108/108 成功。

512 服务启动时自动分配 129312-token KV 池，4096 服务为 143472 tokens。这是修改 budget 后 activation profiling 的连带结果，不是第二个手工调节变量；两组实际 KV 峰值分别只有约 9.5% 与 8.6%，没有触及 KV 边界。完整启动信息见 [512 服务日志](token_budget_server_512_20260923.log)和[4096 服务日志](token_budget_server_4096_20260923.log)。

`*` mixed/512 的 0.1 秒采样没有捕获 Waiting，但 queue-time histogram 的平均值中位数为 0.0455 秒，而 4096 为接近 0；短暂排队可能短于采样间隔。

混合负载按请求长度拆分后的客户端 TTFT P50：

| budget | short | long |
| ---: | ---: | ---: |
| 512 | 1.3710 s（1.3566–2.2216） | 2.4476 s（1.3545–2.4774） |
| 4096 | 0.3775 s（0.2561–1.0028） | 1.0488 s（0.7653–1.0608） |

这说明本次混合负载下，大 budget 没有让短请求变得更慢，反而减少了长 Prefill 尚未完成时对整批首 token 的拖延；与此同时服务端 ITL 略高。TTFT 与 ITL 的方向可以不同，调参不能只看一个指标。

## 如何区分三类限制

| 现象 | 本项目中的证据 | 判定 |
| --- | --- | --- |
| 请求名额限制 | 旧实验 `max-num-seqs=4`，Running=4、Waiting=2、KV 约 1.22%、无抢占 | 序列名额瓶颈 |
| Token budget 限制 | 本实验 long/512，请求数 6 小于名额 8，KV 约 9.4%、无抢占，但 capacity Waiting 2–3；换 4096 后消失 | 单轮 token budget 瓶颈 |
| KV 空间不足 | 受控 1024-block 实验，KV 接近 100%、Preemption counter 增加并出现约 3 秒单请求停顿 | KV 抢占与重算 |

## 原始数据与局限

采集脚本为 [`token_budget_benchmark.py`](../token_budget_benchmark.py)。本次 24 个 JSON（6 个预热、18 个正式）都在[结果目录](.)中，文件名格式为 `token_budget_20260923-19*_512|4096_<shape>_warmup|formal.json`，保存了逐请求事件、完整 metrics 前后快照和 0.1 秒采样。

- 只有两个 budget 点，能够证明“并非单调”，不能绘制完整最优曲线。
- 客户端经过 Mac 和 SSH 隧道，TTFT 有明显尖峰；服务端 histogram 更接近引擎，但只有粗粒度桶和批次平均值。
- 混合负载同时提交，不是精确控制到某个 Decode step 后再注入 Prefill；它能验证重叠干扰，不能定位单个调度轮。
- 输出只有 128 tokens，结论不能外推到超长 Decode 或真实业务分布。
